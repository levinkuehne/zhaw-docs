## Innenteil der klasse

> Es ist sinnvolll, diese reihenfolge einzuhalten

Datenfelder: Speichern die Daten, die da sOjekt nutzt (den zustand)
Konstruktoren: dienen dazu, ein objekt auf einen gültigen anfangsstand zu bringe
methoden: implementation des objektverhalten

### Datenfelder
Speichert Daten und Zustand des Objekts.
Sie sollen sinnvoll gewählt werden und relevant für das Programm sein.

=> Wird als Deklaration bezeichnet

Synonym: **Instanzvariablen** (variable ist zu allgemein)

Datenfelder können im programm geändert werden, müssen aber nicht

Interne Datenfelder sollen mit *private* gekennzeichnet werden. Falls sie überall sichbar sein sollen, dann *public*. (Zugriffsmodifikator)

Zugriffsmodifikator = public/private

deafult zugriffsmodifikator ist package-private. (bisschen tiefer als public)

### Konstruktoren / parameter
konstruktor wird ausgeführt beim erstellen des Objekts
konstruktor definiert anfangszustand

sieht aus wie eine methode
heisst gleich wie die klasse
kein aufrufergebnis > kein ergebnistyp

int hat defaultwert 0
ist trotzdem best practice zum angeben

der wert, der einem konstruktor (oder methode) beim aufruf übergeben wird, wird auch als aktueller paramter bezeichnet.

parameter existiert nur so lange bis die ausführung des konstruktors oder methode beendet ist. => lebensdauer ist auf ausführungszeit beschränkt

 sichtbarkeit des parameters ist auf konstruktor / methode beschränkt
 
### Methoden
methoden braucht es zur interkation von objekten
Methoden dienen dazu, mit einem Objekt zu interagieren • Eine Methode besteht (wie ein Konstruktor) aus einem Kopf und einem Rumpf • Der Kopf ist die „erste Zeile“ der Definition: public int gibPreis() • Der Rumpf ist alles zwischen { und }

methoden rumpf: besteht aus deklarationen und anweisungen
-> wird bei methodenaufruf ausgeführt

rückgabeanweisung mit return xxx; gibt xxx zurück

Methode wird beendet durch:
- rückgabeanweisung
- ende des methodenrumpf

**Sondierende Methoden**
liefert informationen über zustand eines objekts
aufrufergebnis, 
getter methoden => sondieren eines einzelnen datenfeldes

**Verändernde Methoden**
ändert interner zustand eines objektes
oft kein aufrufergebnis
spezialfall setzen eines datenfeldes auf übergebenden wert
