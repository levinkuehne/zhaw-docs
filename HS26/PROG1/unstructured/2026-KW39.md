# Zusammenfassung

### Anhang B–D: Grundlagen

**Primitive Typen (B.1).** Es gibt 8 primitive Datentypen: `byte`, `short`, `int`, `long`, `float`, `double`, `char`, `boolean`. Primitive Typen speichern direkt einen Wert und sind keine Objekte.

- **Ganzzahlen** (`int`, `long`) haben keine Nachkommastellen. **Fliesskommazahlen** (`float`, `double`) haben Nachkommastellen, sind aber nicht immer exakt.
- `int`: 32 Bit, von −2'147'483'648 bis 2'147'483'647 (ca. ±2,1 Milliarden)
- `long`: 64 Bit, ca. ±9,2 · 10¹⁸ (Good to know)
- `boolean`: nur `true` oder `false`
- `double` (64 Bit, ca. 15 Stellen) ist genauer als `float` (32 Bit, ca. 7 Stellen).

**Cast (B.2).** Mit einem Cast wandelst du einen Typ explizit in einen anderen um: `(int) 3.9` ergibt `3`. Dabei wird abgeschnitten, nicht gerundet.

**Wrapper-Klassen (B.4).** Zu jedem primitiven Typ gibt es eine Klasse: `Integer`, `Double`, `Boolean`, `Character` usw. Sie bieten nützliche Methoden, z.B. `Integer.parseInt("42")` oder `Integer.MAX_VALUE`.

**Operatoren (C).**

- Arithmetik: `+ - * / %`
- **Wichtig:** `7 / 2` ergibt `3`, weil Ganzzahldivision den Rest abschneidet. `7.0 / 2` ergibt `3.5`. `7 % 2` ergibt `1`, den Rest.
- **Priorität:** `* / %` vor `+ -`, danach die Vergleiche, dann `&&`, dann `||`. Wie in der Mathematik gilt: Punkt vor Strich.
- **Boolescher Ausdruck:** ein Ausdruck, der `true` oder `false` ergibt. Dazu gehören die Vergleichsoperatoren `==`, `!=`, `<`, `>`, `<=`, `>=` und die logischen Operatoren `&&` (und), `||` (oder), `!` (nicht).
- **Abkürzungsoperatoren:** Bei `a && b` wird `b` nicht mehr ausgewertet, wenn `a` schon `false` ist. Bei `a || b` wird `b` nicht ausgewertet, wenn `a` schon `true` ist.
- `^` (Good to know): exklusives Oder. Das Ergebnis ist `true`, wenn genau einer der beiden Werte `true` ist.

**if-else (D.2.1).** Der `else`-Zweig ist optional. Mit `else if` kannst du mehrere Bedingungen verketten.

### Kapitel 1: Objekte und Klassen

- **Klasse vs. Objekt:** Die Klasse ist der Bauplan, z.B. «Kreis». Ein Objekt (auch Instanz) ist ein konkretes Exemplar davon, z.B. ein bestimmter roter Kreis. Von einer Klasse kann es viele Objekte geben.
- **`new`** erzeugt ein neues Objekt, z.B. `new Kreis()`.
- **Methoden** sind das, was ein Objekt tun kann. Du rufst sie auf dem Objekt auf. **Parameter** liefern der Methode zusätzliche Informationen, z.B. `bewegeHorizontal(50)`.
- **Signatur** (Good to know): Name der Methode plus die Parametertypen.
- **Zustand:** die aktuellen Werte aller Datenfelder eines Objekts.
- **Datenfelder:** In der Klasse steht nur der _Name_ des Feldes, z.B. `farbe`. Jedes Objekt hat seine _eigene_ Kopie davon mit eigenem Wert. Zwei Kreise können also unterschiedliche Farben haben.
- **Objektinteraktion:** Objekte rufen Methoden anderer Objekte auf. Du solltest verfolgen können, in welcher Reihenfolge was passiert.
- **Übersetzung (Compilierung):** Der Quelltext wird in eine Form übersetzt, die der Computer ausführen kann. Nach jeder Änderung muss neu übersetzt werden.
- **Aufrufergebnis:** Eine Methode kann einen Wert zurückliefern, z.B. `gibName()` liefert einen String.

### Kapitel 2: Klassendefinitionen

**Aufbau einer Klasse:**

```java
public class Ticketautomat {
    private int preis;              // Datenfeld (immer private!)

    public Ticketautomat(int ticketpreis) {   // Konstruktor
        preis = ticketpreis;
    }

    public int gibPreis() {         // Methode
        return preis;
    }
}
```

- Das Schlüsselwort ist **`class`**.
- **Datenfelder** sind `private`. Sie speichern den Zustand des Objekts.
- Der **Konstruktor** hat _denselben Namen wie die Klasse_ und keinen Rückgabetyp. Er initialisiert das Objekt, wenn es mit `new` erzeugt wird.
- **Formaler Parameter:** der Name in der Methodendefinition, hier `ticketpreis`. **Aktueller Parameter:** der konkrete Wert beim Aufruf, z.B. `1000`.

**Methoden (2.7, 2.10):**

- Eine Methode besteht aus Kopf (Sichtbarkeit, Rückgabetyp, Name, Parameter) und Rumpf.
- **`return`** liefert einen Wert zurück und beendet die Methode sofort. `void` bedeutet, dass nichts zurückgegeben wird.
- _Sondierende Methoden_ (Getter) fragen den Zustand ab. _Verändernde Methoden_ (Setter) ändern ihn. (Good to know)

**Ausgabe (2.9):** `System.out.println("Preis: " + preis + " Cent");`. Das `+` verknüpft Strings. Sobald ein String beteiligt ist, wird alles zu Text zusammengehängt.

**Bedingte Anweisung (2.13/2.14):**

```java
if (betrag > 0) {
    bisherGezahlt = bisherGezahlt + betrag;
} else {
    System.out.println("Bitte positiven Betrag angeben.");
}
```

**Lebensdauer von Variablen (2.16/2.17), sehr wichtig:**

|Art|Wo deklariert?|Lebensdauer|
|---|---|---|
|Datenfeld|in der Klasse, ausserhalb von Methoden|so lange wie das Objekt|
|Parameter|im Methoden- oder Konstruktorkopf|nur während des Aufrufs|
|Lokale Variable|im Methodenrumpf|nur bis zum Ende ihres Blocks|

**2.21 (Good to know):** Du kannst Ergebnisse direkt weiterverwenden, z.B. `System.out.println(t.gibPreis());`, ohne sie vorher in einer Variable zu speichern.

### Die Übungen

Alle beziehen sich auf den **Ticketautomaten** (Projekt _Besserer-Ticketautomat_).

**2.46 (Good to know).** Erzeuge einen Ticketautomaten und rufe `geldEinwerfen` mit verschiedenen Beträgen auf, auch mit 0 und negativen Werten. Prüfe, ob sich `bisherGezahlt` ändert, wenn eine Fehlermeldung kommt.  
_Antwort:_ Bei 0 oder negativen Beträgen bleibt `bisherGezahlt` unverändert, weil nur der else-Zweig mit der Fehlermeldung läuft.

**2.51 (Good to know).** Kann man in `ticketDrucken` den `else`-Teil weglassen? Übersetzt es noch? Was passiert, wenn man ohne Geld ein Ticket drucken will?  
_Antwort:_ Ja, es übersetzt, weil `else` optional ist. Ohne Geld passiert dann einfach nichts, es kommt auch keine Meldung.

**2.58 (Good to know).** Warum ist diese Version falsch?

```java
bisherGezahlt = 0;
return bisherGezahlt;
```

_Antwort:_ Der Wert wird zuerst auf 0 gesetzt und danach zurückgegeben. Es wird also immer 0 zurückgegeben. Genau deshalb braucht man eine lokale Variable, die den alten Wert zwischenspeichert.

**2.59 (Good to know).** Was passiert hier beim Übersetzen?

```java
return bisherGezahlt;
bisherGezahlt = 0;
```

_Antwort:_ Es gibt einen Compilerfehler («unreachable statement»). Nach `return` ist die Methode beendet, die Zeile danach kann nie ausgeführt werden.

**2.60 (Must know, häufiger Fehler!).** Was ist falsch an diesem Konstruktor?

```java
public Ticketautomat(int ticketpreis) {
    int preis = ticketpreis;   // ← Problem!
    ...
}
```

_Antwort:_ Durch `int` davor wird eine **neue lokale Variable** `preis` erzeugt, die das Datenfeld `preis` überdeckt. Der Wert landet in der lokalen Variable und verschwindet am Ende des Konstruktors. Das Datenfeld bleibt 0, das siehst du im Inspektor. Der Code übersetzt trotzdem, was diesen Fehler so tückisch macht.

**2.79 (Good to know).** Sage die Ergebnisse voraus und prüfe sie in der Direkteingabe:

|Ausdruck|Ergebnis|Warum|
|---|---|---|
|`99 + 3`|`102`|normale Addition|
|`"See" + "wolf"`|`"Seewolf"`|String-Verkettung|
|`"See" + 9`|`"See9"`|Zahl wird zu Text|
|`9 + 3 + "See"`|`"12See"`|von links: zuerst 9+3=12, dann Text|
|`"See" + 3 + 9`|`"See39"`|von links: zuerst Text, danach wird alles angehängt|
|`"Seewolf".substring(3,4)`|`"w"`|Zeichen ab Index 3 bis vor Index 4|
|`"Seewolf".substring(3,8)`|Fehler|Index 8 existiert nicht (Länge 7)|

**2.80–2.82 (Must know, Verständnis für Instanzen).** In der Direkteingabe:

- **2.80:** `Ticketautomat t1 = new Ticketautomat(1000);` und dann `t1.gibBisherGezahltenBetrag()` abfragen, Geld einwerfen und erneut abfragen. Achte darauf, dass Zeilen ohne Semikolon den Wert anzeigen. (Im Buch steht `geldEinwerfen()` ohne Parameter. Das ergibt einen Fehler, weil ein Betrag erwartet wird.)
- **2.81:** `Ticketautomat t2 = t1;`. Was liefert `t2.gibBisherGezahltenBetrag()`? Denselben Wert wie `t1`.
- **2.82:** `t1.geldEinwerfen(500);` und dann `t2.gibBisherGezahltenBetrag()` abfragen.  
    _Antwort:_ `t2` zeigt ebenfalls die 500 an. **Kernaussage:** `t2 = t1` kopiert nicht das Objekt, sondern nur die **Referenz**. Beide Variablen zeigen auf _dasselbe_ Objekt. Es gibt nur einen Ticketautomaten.

## Begriffe

- **Objekt**: Java-Objekte modellieren Objekte eines Anwendungsbereichs.
- **Klasse**: Objekte werden durch Klassen erzeugt. Eine Klasse beschreibt eine bestimmte Art von Objekten; Objekte repräsentieren individuelle Instanzen einer Klasse.
- **Methode**: Wir können mit Objekten kommunizieren, indem wir ihre Methoden aufrufen. Ein Objekt tut üblicherweise etwas, wenn eine seiner Methoden aufgerufen wird.
- **Parameter**: Methoden können Parameter haben, mit denen zusätzliche Informationen für eine Aufgabe angegeben werden.
- **Signatur**: Der Name und die Parametertypen einer Methode werden als deren Signatur bezeichnet. Sie benennt die benötigten Informationen für einen Aufruf der Methode.
- **Typ**: Parameter haben Typen. Ein Typ definiert, welche Arten von Werten ein Parameter annehmen kann.
- **Eine Klasse, viele Instanzen**: Von einer Klasse können viele gleichartige Instanzen erzeugt werden.
- **Zustand**: Objekte haben einen Zustand. Dieser Zustand wird durch Werte repräsentiert, die in Datenfeldern gehalten werden.
- **Methodenaufrufe**: Objekte können miteinander kommunizieren, indem sie gegenseitig ihre Methoden aufrufen.
- **Quelltext**: Der Quelltext einer Klasse legt die Struktur und das Verhalten (die Datenfelder und die Methoden) aller Instanzen dieser Klasse fest.
- **Ergebnis**: Methoden können Informationen über ein Objekt durch einen Ergebniswert zurückliefern.
- **Objekterzeugung**: Einige Objekte können nur dann erzeugt werden, wenn zusätzliche Informationen bereitgestellt werden.
- **Datenfeld**: Datenfelder speichern die Daten, die ein Objekt benutzt. Datenfelder werden auch als Instanzvariablen bezeichnet.
- **Kommentar**: Kommentare werden im Quelltext einer Klasse angegeben, um menschlichen Lesern das Verstehen des Codes zu erleichtern. Sie haben keinen Einfluss auf die Funktionalität einer Klasse.
- **Konstruktor**: Konstruktoren ermöglichen, dass ein Objekt nach seiner Erzeugung in einen gültigen Zustand versetzt wird.
- **Sichtbarkeit**: Durch die Sichtbarkeit einer Variablen wird der Bereich innerhalb des Quelltextes definiert, in dem eine Variable zugreifbar ist.
- **Lebensdauer**: Die Lebensdauer einer Variablen legt fest, wie lange sie existiert, bevor sie zerstört wird.
- **Zuweisung**: Zuweisungen speichern den Wert auf der rechten Seite eines Zuweisungsoperators in der Variablen, die auf der linken Seite genannt ist.
- **Sondierende Methode**: Sondierende Methoden liefern Informationen über den Zustand eines Objekts.
- **Verändernde Methode**: Verändernde Methoden ändern den Zustand eines Objekts.
- **println**: Die Methode System.out.println gibt ihren Parameter auf der Konsole aus.
- **Bedingte Anweisung**: Eine bedingte Anweisung führt eine von zwei Aktionen aus, abhängig vom Ergebnis einer Prüfung.
- **Boolescher Ausdruck**: Boolesche Ausdrücke haben nur zwei mögliche Werte: wahr (true) und falsch (false). Sie werden oft verwendet, um die Auswahl zwischen zwei Ausführungspfaden in einer bedingten Anweisung zu treffen.
- **Lokale Variable**: Eine lokale Variable ist eine Variable, die innerhalb einer Methode deklariert und benutzt wird. Sie ist nur innerhalb der Methode zugreifbar und ihre Lebensdauer entspricht der ihrer Methode
